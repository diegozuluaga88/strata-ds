# Strata DS — Governance

This folder is the source of truth for every Strata Design System rule and anti-pattern — **how** the system is applied and how elements behave. The token reference here documents the values this repo generates; for **what exists** in a consumer's hands, the published package is what counts (see *On authority* below). Three audiences consume it:

1. **The DS app at `localhost:5173`** — renders each `.md` file via `GovernanceView`.
2. **The MCP server** (`strata-ds`) — exposes the markdown files as tools (`get_laws`, `get_rules({category})`, `get_tokens`, `get_anti_patterns`, `search_governance`, `get_overview`, `validate_component_against_rules`).
3. **The static HTML guide** — `rules-guide.html`, published to GitHub Pages via the workflow in `.github/workflows/publish-rules-guide.yml`.

## Generating the HTML guide

```bash
npm run build:guide
# → governance/rules-guide.html (~500 KB · 21 sidebar sections)
```

Open `governance/rules-guide.html` directly in any browser. Works offline (zero external deps, all CSS + JS inline). Light/dark toggle in the header. Every code block has a copy-to-clipboard button.

## Publishing to GitHub Pages

Set up once by an admin:

1. Repo → Settings → Pages → Source: **GitHub Actions**
2. (Optional) Add a custom domain

After that the workflow at `.github/workflows/publish-rules-guide.yml` deploys automatically when files under `governance/` change on `main`. Manual deploy via Actions → "Publish rules guide to GitHub Pages" → Run workflow.

## Running the corrections miner

```bash
node governance/mine-corrections.mjs
# → governance/correction-patterns-diagnostic.md
```

Scans `~/.claude/projects/` for past Claude Code sessions in Strata-related projects, detects correction signals, buckets by topic, ranks by strength score. Output is anonymized at persist time.

## MCP server

Started by `npm run server` (HTTP on `:3001`) or `npm run server:dev` (watched).

### Source resolution (F38.2)

The server reads governance via a 4-step source layer:

1. `STRATA_LOCAL_ROOT` env var — explicit override (used when developing locally)
2. GitHub tarball fetched via `gh` CLI, cached at `~/.cache/strata-ds-mcp/<sha>/` (10 min TTL on the SHA lookup)
3. Most-recent cached SHA when offline / `gh` is missing
4. Bundled `governance/` shipped next to the binary

No env vars or tokens required — the `gh` CLI uses the user's existing session. Everything fetched is attributed to that user (so `report_error` opens issues correctly).

### Tools exposed (15 total)

| Tool | Returns |
|------|---------|
| `get_session_briefing()` | Compact start-of-session briefing (laws + rule headlines + workflow). Call this first. |

| `get_rules({category})` | 17 rule categories (rules/01-16 + code-usage) |

| `search_governance({query})` | full-text search across the folder |
| `get_overview()` | LAWS + tokens + anti-patterns + h2 headings of every rule |
| `get_component({id})` | component spec |

| `report_error({description, context?})` | log a DS gap |

### Comparison with the storybook MCP (PR #20)

The `AvantoDev/front-react-strata-storybook` repo ships a sibling MCP server in PR #20. Both consume the SAME `governance/` markdown source (this folder), so the rule content is in lockstep.

| | This repo (`@diegoagentic/strata-ds`) | Storybook (`@avantodev/strata-design-system`) |
|---|---|---|
| Transport | stdio + HTTP `:3001` | stdio only |
| Source | gh-tarball + cache + bundled (F38.2) | gh-tarball + cache + bundled |
| Lint tool | ✅ `validate_component_against_rules` (22 checks) | — |
| Session briefing | ✅ `get_session_briefing` | ✅ `get_session_briefing` |
| Version check | ✅ `check_version` | ✅ `check_version` |
| Component catalog | ✅ `list_components` | ✅ `list_components` |
| Agent Skill | ✅ `install_skill` (planning-strata-ui) | ✅ `install_skill` (planning-strata-ui) |
| Component spec | ✅ `get_component` | ✅ `get_component` |
| Error reporting | `report_error` (logs only) | `report_error` (opens GitHub issue) |

Either MCP can be consumed by the same Strata project. The dev team's MCP is the recommended choice when consuming Strata from the published storybook; this one is the reference for **how** the system is applied — the governance and the linter, which live only here.

**On authority, because these lines used to say the opposite.** The published package rules on **what exists**: components, variants, props, tokens. It is the delivery boundary, and whatever is not in it does not exist for the consumer regardless of how well it is documented here. This repo rules on **how it is applied** and how elements behave. Calling this repo the "canonical reference" without that split is how a token nobody can consume ends up recommended — measured on 2026-10-21, 11 of the 139 `--color-*` tokens here are not in the published package.

Note also that the `:3001` HTTP transport is **not hosted**: paying for it was deferred. Nothing here depends on it — the MCP also speaks stdio, its source is the GitHub tarball cached under `~/.cache/strata-ds-mcp/<sha>/`, and `rules-guide.html` opens offline with no dependencies. What that does mean is that **governance changes only reach agents once they are pushed**, since the tarball comes from GitHub and not from a working copy.

## Editing rules

1. Edit the `.md` directly.
2. Regenerate the HTML: `npm run build:guide`.
3. Test the MCP if you renamed a file: `npm run server` then call the tool.
4. Commit — the GitHub Pages deploy happens on merge to main.

For new rule categories, also update:

- `src/mcp-server/mcp.ts` and `src/mcp-server/mcp-http.ts` — add to the `get_rules` enum + fileMap (both files must stay in sync).
- `governance/build-guide.mjs` — add to the `SECTIONS` array so the HTML guide picks it up.
- `governance/examples-data.mjs` — optional ve-block visual examples keyed by heading slug.
